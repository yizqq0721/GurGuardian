# FurGuardian · 云服务器部署说明（MySQL 8 + Redis 8）

> 目标机器：阿里云 ECS · Ubuntu 24.04 LTS · root 登录
> 目标：一条 `docker compose up -d` 起好数据库和 Redis，队友通过 SSH 隧道或安全组白名单连接。
> 本文所有命令都在 **服务器上** 执行，特别标注的除外。

---

## 0. 先看三个结论

| 结论 | 原因 |
| --- | --- |
| **必须用 Docker 跑 Redis，不要 `apt install redis-server`** | Ubuntu 24.04 源里是 Redis 7.0.x，**没有 Query Engine**（`FT.CREATE` 直接报 unknown command），向量检索整条链路会废掉。项目要求 Redis ≥ 8.0。 |
| **SQL 不能整个目录挂给 MySQL 初始化** | 容器按**文件名排序**执行 `docker-entrypoint-initdb.d/*.sql`：`knowledge_seed.sql` 会排在 `schema.sql` 前面 → 表还没建就插数据，必失败。本仓库的 `docker-compose.yml` 已改成显式挂 `01/02/03`。 |
| **3306 / 6379 不要对 `0.0.0.0/0` 开放** | 公网上的 MySQL/Redis 扫描是分钟级的，弱口令 Redis 通常几小时内被挖矿。默认走 SSH 隧道，或安全组只放行队友 IP。 |

另外：**初始化 SQL 只在数据卷为空时执行一次**。以后改了 `sql/*.sql`，要么手动进容器执行，要么 `docker compose down -v` 重建（会删数据）。

## 1. 目录约定

把仓库根目录（含 `pom.xml`、`sql/` 的那一层）放到服务器 `/opt/furguardian`：

```
/opt/furguardian/
├── docker-compose.yml      ← 本仓库新增
├── .env                    ← 由 .env.example 复制而来，含真实密码
├── .env.example
├── sql/
│   ├── schema.sql          ← 13 张表
│   ├── seed.sql            ← demo 账号 + 2 只宠物 + 8 周体重
│   └── knowledge_seed.sql  ← 80 条知识语料
└── ...（后端模块、前端目录）
```

## 2. 安装 Docker（含国内镜像加速）

```bash
# 方式 A：官方脚本 + 阿里云镜像源
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun

# 方式 B（A 失败时）：Ubuntu 源
apt update && apt install -y docker.io docker-compose-v2

systemctl enable --now docker
docker --version
docker compose version     # 注意是 compose（v2 插件），不是 docker-compose
```

配置镜像加速（否则拉 `redis:8.10.2` 可能很慢或超时）：

1. 阿里云控制台 → 容器镜像服务 ACR → 镜像工具 → 镜像加速器，拿到专属地址 `https://<你的ID>.mirror.aliyuncs.com`
2. 写入配置：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://<你的ID>.mirror.aliyuncs.com"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
systemctl restart docker
```

## 4. 生成密码

```bash
cd /opt/furguardian
cp .env.example .env

# 生成三个 32 位随机密码并直接替换（Linux 上执行）
sed -i "s/CHANGE_ME_root_openssl_rand_hex_16/$(openssl rand -hex 16)/" .env
sed -i "s/CHANGE_ME_app_openssl_rand_hex_16/$(openssl rand -hex 16)/"  .env
sed -i "s/CHANGE_ME_redis_openssl_rand_hex_16/$(openssl rand -hex 16)/" .env

cat .env      # 记下来，本机 application-local.yml 要用
chmod 600 .env
```

> `.env` 已加入 `.gitignore`，不会进仓库。密码只用十六进制，避免 `$`、`#` 破坏 compose 插值。

## 5. 启动并初始化

```bash
cd /opt/furguardian
docker compose up -d
docker compose ps                 # 两个服务都应是 healthy
docker compose logs --tail=50 mysql
```

首次启动会自动按顺序执行：`01-schema.sql` → `02-seed.sql` → `03-knowledge_seed.sql`。

## 6. 验收清单（逐条对）

```bash
set -a; . ./.env; set +a     # 把 .env 读进当前 shell

# 1) MySQL 版本 + 时区 + 字符集
docker exec pet-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e \
  "SELECT VERSION() AS ver, @@time_zone AS tz, @@character_set_server AS cs;"

# 2) 表数量应为 13；知识 80 条；食品 3 条；用户 demo
docker exec pet-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "
SELECT COUNT(*) AS tables_cnt FROM information_schema.tables WHERE table_schema='fur_guardian';
SELECT COUNT(*) AS knowledge FROM fur_guardian.knowledge_docs;
SELECT COUNT(*) AS foods FROM fur_guardian.foods;
SELECT COUNT(*) AS pets  FROM fur_guardian.pets;
SELECT username FROM fur_guardian.users;"

# 3) Redis 必须是 8.x（关键！）
docker exec pet-redis redis-cli -a "$REDIS_PASSWORD" INFO server | grep redis_version

# 4) Query Engine 在不在（能返回空列表就说明命令可用）
docker exec pet-redis redis-cli -a "$REDIS_PASSWORD" FT._LIST
```

期望结果：`tables_cnt=13`、`knowledge=80`、`foods=3`、`pets=2`、`users=demo`、`redis_version:8.x`。

如果第 4 步报 `unknown command 'FT._LIST'`，说明镜像不对（拉成了 Redis 7），换 `redis:8.10.2` 重来。

## 7. 连接方式（三选一）

### A. 后端也部署在这台 ECS 上（最安全，演示推荐）

`BIND_ADDR` 保持 `127.0.0.1`，应用直接连 `127.0.0.1:3306` / `127.0.0.1:6379`。
安全组只开 22（限自己 IP）和 80/443（如果要给评委访问）。

### B. 本机开发，走 SSH 隧道（安全，推荐）

Windows PowerShell 里另开一个窗口，保持不关：

```powershell
ssh -N -o ServerAliveInterval=30 `
  -L 3307:127.0.0.1:3306 `
  -L 6380:127.0.0.1:6379 `
  root@<公网IP>
```

然后本机把数据库当 `127.0.0.1:3307`、Redis 当 `127.0.0.1:6380` 用。
好处：服务器端口不需要对公网开放，安全组一条规则都不用加。

### C. 安全组白名单直连（方便，但要看住 IP）

`BIND_ADDR=0.0.0.0` 后 `docker compose up -d`，然后阿里云控制台 → 安全组 → 入方向：

| 端口 | 授权对象 |
| --- | --- |
| 22 | 你的固定 IP/32 |
| 3306 | 队友的公网 IP/32（每人一条） |
| 6379 | 同上，能不开就不开 |

⚠️ **不要用 `0.0.0.0/0`**。另外 Docker 发布端口会绕过 `ufw`，真正生效的是**安全组**，别只配 ufw。

## 8. 本机后端接上去

编辑 `pet-web/src/main/resources/application-local.yml`（该文件已被 `.gitignore` 排除）：

```yaml
spring:
  datasource:
    # 隧道方案：端口用 3307；直连方案改成 <公网IP>:3306
    url: jdbc:mysql://127.0.0.1:3307/fur_guardian?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: fur
    password: <MYSQL_PASSWORD>
  data:
    redis:
      host: 127.0.0.1      # 直连方案改成 <公网IP>
      port: 6380           # 直连方案改成 6379
      password: <REDIS_PASSWORD>
langchain4j:
  community:
    redis:
      host: 127.0.0.1
      port: 6380
      password: <REDIS_PASSWORD>
    dashscope:
      chat-model:
        api-key: <你的 DashScope Key>
      embedding-model:
        api-key: <同一个 Key>
```

两个容易踩的点：

- **`DASHSCOPE_API_KEY` 环境变量不会自动生效**。`application.yml` 里写的是字面量 `your-dashscope-api-key`，不是 `${DASHSCOPE_API_KEY}`，所以必须像上面这样在 `application-local.yml` 里覆盖，或者先把 yml 改成 `${DASHSCOPE_API_KEY:}`。
- **Redis 有两处配置**：Spring 自己的 `spring.data.redis`（token 缓存）和 `langchain4j.community.redis`（向量库），两个都要改，只改一个会出现"能登录但 RAG 连不上"。

## 9. 部署前必须改的两处代码

### 9.1 demo 账号密码对不上（不改必然登不进去）

`sql/seed.sql` 第 11 行的 BCrypt 哈希，实测是 `123456` 的哈希，而前端 `AuthView.vue` 提示的是 `demo123`。

部署前在 Windows 上生成一个 `demo123` 的哈希（用项目已有的 `spring-security-crypto` jar，路径按自己 `.m2` 调整）：

```powershell
jshell --class-path "$env:USERPROFILE\.m2\repository\org\springframework\security\spring-security-crypto\7.1.1\spring-security-crypto-7.1.1.jar"
```

进去后执行：

```java
import org.springframework.security.crypto.bcrypt.BCrypt;
System.out.println(BCrypt.hashpw("demo123", BCrypt.gensalt(10)));
```

把输出的 `$2a$10$...` 替换掉 `seed.sql` 第 11 行的哈希，**然后再初始化数据库**。
如果已经初始化了，也可以直接改库：

```sql
UPDATE fur_guardian.users
SET password = '$2a$10$替换成新哈希'
WHERE username = 'demo';
```

> 不想开 jshell 也行：在服务器上装 `apache2-utils`，用
> `htpasswd -bnBC 10 "" demo123 | cut -d: -f2`
> 生成 `$2y$10$...`，Spring 的 `BCryptPasswordEncoder` 同样认（2y 等价于 2a）。

### 9.2 向量入库没有入口（RAG 现在只能走 SQL 兜底）

`EmbeddingIngestionService` 在仓库里**没有任何调用方**，80 条语料只进 MySQL、`embedding_id` 全空。
所以即使 Redis 起好了，`FT._LIST` 也会是空的，检索会一直降级成 SQL。

部署完基础设施后，需要补一个触发入口（例如受保护的 `POST /api/knowledge/reindex`，或启动时按开关执行 `ingestAllUnembedded()`），再验证索引里有数据。

## 10. 备份 / 恢复 / 重置

```bash
# 备份（在服务器上，导到当前目录）
set -a; . ./.env; set +a
docker exec pet-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --databases fur_guardian' \
  > backup-$(date +%F-%H%M).sql

# 恢复（--default-character-set 必须带，否则中文会存成双重编码乱码，见 deploy/fix-mojibake-utf8mb4.sql）
docker exec -i pet-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4' < backup-2026-10-17-2200.sql

# 停止但保留数据
docker compose down

# 连数据一起删（下次 up 会重新跑初始化 SQL）
docker compose down -v
```

演示前一天一定做一次备份，并把 `backup-*.sql` 拉回本地留一份。

## 11. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `unknown command 'FT._LIST'` | Redis 版本不够（`INFO server` 会显示 6.x/7.x）。**注意**：阿里云 ACR 加速器的 `redis` 缓存停在 6.2.6，`redis:8` 全 404；要从 `docker.m.daocloud.io/library/redis:latest` 拉（实测 8.10.2） |
| 容器起来但表是空的 | 初始化脚本只在数据卷为空时跑；`docker compose down -v` 后重来 |
| 日志里 `knowledge_docs doesn't exist` | 有人把整个 `sql/` 目录挂进去了，顺序乱了；用仓库里的 compose |
| 本机连不上 3306 | 先看 `docker compose ps` 端口绑定是 `127.0.0.1` 还是 `0.0.0.0`，再查安全组 |
| 中文变问号 | 客户端没带字符集；JDBC URL 里保留 `characterEncoding=UTF-8`，手工导入时先 `SET NAMES utf8mb4;` |
| 中文变成 `æ¼”ç¤ºç”¨æˆ·` 这种西欧字母乱码 | 导入时客户端按 latin1(=cp1252) 读了 UTF-8 文件，中文被逐字节误存成 3 个字母 = **双重编码，脏数据已经进了库**。JDBC 侧改配置没用，得修数据：`deploy/fix-mojibake-utf8mb4.sql`。预防：`sql/*.sql` 里已加 `SET NAMES utf8mb4;`，命令行导入再补 `--default-character-set=utf8mb4` |
| 拉镜像超时 | 没配镜像加速，或 `redis:8.10.2` 该 tag 不可用 → 换 `redis:8` 再 `INFO server` 确认 |
| `docker compose` 找不到 | 装的是老版 `docker-compose` v1；用 `docker compose`（v2 插件） |
| 磁盘涨得快 | compose 里已限制日志轮转；另外别把 `backup-*.sql` 长期堆在服务器上 |
